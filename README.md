# RK — Private Edition

Сайт бренда RK — Private Edition: парфюмерия (RK — Parfum), заглушка Studio Pod Shade,
переход на MemoryPhone и каталог RK — 3D Print. Next.js 16 (App Router) + TypeScript +
Tailwind CSS + Supabase (база данных, авторизация, хранилище файлов) + GSAP (скролл-анимации)
+ уведомления о заказах в Telegram + отдельный Telegram-бот-магазин с тем же каталогом.

Работа ведётся локально в VS Code, без деплоя — репозиторий GitHub не трогаем.

---

## 1. Что нужно установить один раз

1. **Node.js 20+** — https://nodejs.org (проверить: `node -v`)
2. **VS Code** (не Visual Studio!) — https://code.visualstudio.com
3. Расширения VS Code (по желанию, но удобно): *ESLint*, *Tailwind CSS IntelliSense*.

## 2. Настройка Supabase (база данных, вход, хранилище)

Supabase — бесплатный (на старте) облачный Postgres с готовой авторизацией и файловым
хранилищем. Аккаунт бренда там регистрировать не нужно — только ваш личный, как у
разработчика.

1. Зайдите на https://supabase.com → **New project**.
   - Задайте пароль базы данных (сохраните его отдельно, он не нужен для сайта, но
     пригодится, если понадобится прямой доступ к БД).
   - Регион — ближайший к вашим клиентам (например, Frankfurt/EU).
2. Дождитесь создания проекта, затем откройте **SQL Editor** → **New query**.
3. Откройте файл [`supabase/schema.sql`](./supabase/schema.sql) из этого репозитория,
   скопируйте всё содержимое, вставьте в SQL Editor и нажмите **Run**.
   Это создаст все таблицы, политики безопасности (RLS), функции входа по логину и бакеты
   для фото товаров/отзывов.
   **Если у вас уже был настроен этот проект раньше** (база не создаётся с нуля) — `schema.sql`
   не добавит новые столбцы/политики в уже существующие таблицы сам по себе, поэтому выполните
   ещё и файлы `supabase/migration_telegram_bot.sql` и
   `supabase/migration_volume_options_and_order_delete.sql` (безопасно выполнять в любом порядке
   и повторно).
4. (Опционально, для тестовых товаров) откройте
   [`supabase/seed_demo_products.sql`](./supabase/seed_demo_products.sql), тоже вставьте в
   SQL Editor и выполните — появятся 3 тестовых парфюма и 3 тестовых 3D-объекта с
   SVG-заглушками фото. Их можно удалить или отредактировать позже из админки.
5. Перейдите в **Project Settings → API** и скопируйте:
   - `Project URL` → это `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public` key → это `NEXT_PUBLIC_SUPABASE_ANON_KEY`
6. Перейдите в **Authentication → Providers → Email** и по желанию отключите
   **Confirm email** («Confirm email» → Off). Это не обязательно: профиль пользователя
   создаётся автоматически при регистрации в любом случае, но если подтверждение почты
   включено, покупатель не сможет войти, пока не перейдёт по ссылке из письма. Для приватного
   бутик-бренда обычно удобнее отключить подтверждение.
7. В **Authentication → URL Configuration** укажите `Site URL` = адрес сайта (для локальной
   разработки — `http://localhost:3000`, позже смените на боевой домен).

### Важно про безопасность

- Все данные защищены Row Level Security (RLS): пользователь видит только свои заказы,
  редактировать товары/заказы/пользователей может только аккаунт с `is_admin = true`.
- Пароль администратора **не хранится в коде**. Как назначить администратора — см.
  раздел 6 ниже.

## 4. Telegram-уведомления о заказах

Когда покупатель оформляет заказ (парфюм или 3D-печать), сообщение со всеми деталями
(номер заказа, состав, сумма, контакты покупателя) автоматически приходит вам в Telegram.

1. В Telegram напишите **@BotFather** → `/newbot` → задайте имя и username бота.
   BotFather выдаст **токен** вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`.
   Вставьте его в `.env.local` как `TELEGRAM_BOT_TOKEN`.
2. Решите, куда должны приходить уведомления:
   - **Личный чат** — напишите своему боту любое сообщение (чтобы он мог написать вам первым).
   - **Группа** (рекомендуется, если заказы должны видеть несколько человек) — создайте группу,
     добавьте в неё бота и **сделайте его администратором группы** (это обязательно — иначе
     Telegram по умолчанию не показывает боту обычные сообщения участников). Затем отправьте в
     группе любое сообщение.
3. Узнайте `chat_id` (личного чата или группы): запустите сайт (`npm run dev`) и откройте
   **`http://localhost:3000/api/telegram-chats`** — там будет список всех чатов, которые видит
   бот, с их `chat_id` и названием. Скопируйте нужный.
   (Для группы это число отрицательное, например `-1001234567890` — это нормально.)
4. Впишите этот `chat_id` в `.env.local` как `TELEGRAM_CHAT_ID` и перезапустите `npm run dev`.
5. Проверьте, что всё работает: откройте **`http://localhost:3000/api/telegram-test`** — эта
   страница пошагово проверит токен, chat_id и отправит тестовое сообщение, показав точный
   ответ Telegram, если что-то не так.

Если переменные не заданы, сайт продолжит работать (заказ создастся в базе), просто
уведомление в Telegram не отправится — это видно в логах сервера.

## 5. Telegram-бот-магазин

Помимо уведомлений, в проекте есть отдельный Telegram-бот — полноценный магазин внутри
Telegram: клиент листает каталог парфюмерии и 3D-изделий, добавляет в корзину и оформляет
заказ прямо в переписке с ботом, без захода на сайт. Каталог и заказы — те же самые таблицы
Supabase, что и у сайта: товар, добавленный в админке, сразу появляется и на сайте, и в боте;
заказ из бота сразу виден в админке (с пометкой «Telegram»).

Это отдельный процесс (`npm run bot`), который запускается вместе с сайтом, но независимо от
него — если бот выключен, сайт работает как обычно, и наоборот.

### Настройка

1. Бот использует того же бота, что и уведомления о заказах — `TELEGRAM_BOT_TOKEN` уже должен
   быть в `.env.local` (раздел 4). Если ещё не создавали бота — сделайте это сейчас через
   **@BotFather**.
2. Добавьте в `.env.local` **`SUPABASE_SERVICE_ROLE_KEY`** — без него бот сможет показывать
   каталог, но не сможет создавать заказы (у клиента бота нет аккаунта на сайте, поэтому
   обычный `anon` key с его правилами безопасности для записи заказов не подходит). Найдите
   ключ в Supabase: **Project Settings → API → service_role secret**.
   **Это секретный ключ, обходящий все правила безопасности базы данных — никогда не
   используйте его на сайте и никому не показывайте.**
3. Если проект Supabase был создан **до** появления бота (т.е. вы уже когда-то выполняли
   `supabase/schema.sql`), выполните ещё один файл в SQL Editor:
   [`supabase/migration_telegram_bot.sql`](./supabase/migration_telegram_bot.sql) — он донастраивает
   таблицу заказов под заказы из бота (безопасно выполнять и на новом проекте — просто ничего
   не изменит).
   Если проект создаётся заново — этого шага не нужно, всё уже включено в `schema.sql`.
4. Запустите бота:

   ```bash
   npm run bot
   ```

   В терминале должно появиться «RK Telegram bot запущен (long polling)». Если вместо этого
   сразу выходит ошибка — она подскажет, какая переменная окружения не задана.
5. Напишите боту `/start` в Telegram и попробуйте пройти путь: каталог → товар → в корзину →
   оформить заказ. Заказ появится в **Админка → Заказы** с меткой «Telegram».

Бот можно запускать одновременно с сайтом (`npm run dev` в одном терминале, `npm run bot` — в
другом) или отдельно, если нужен только он.

## 6. Активация администратора

Пароль администратора нигде не хранится в репозитории — вы задаёте его сами при
регистрации.

1. Запустите сайт локально (раздел 6) и зарегистрируйтесь на `/register`, указав почту
   `romankorcagin173@gmail.com` и пароль, который хотите использовать для входа в админку.
   (Логин и телефон/Telegram — любые, это просто ваш профиль.)
2. Откройте Supabase → **SQL Editor** и выполните:

   ```sql
   update public.profiles set is_admin = true where email = 'romankorcagin173@gmail.com';
   ```

3. Войдите на сайте на `/login` под этой почтой/логином и паролем — вас автоматически
   перенаправит в `/admin`.

Админку можно открыть в любой момент по адресу `/admin`.

### Что доступно в админке

- **Обзор** — количество зарегистрированных пользователей, всего/выполненных заказов, оборот.
- **Товары** — добавление/редактирование/удаление товаров для RK — Parfum и RK — 3D Print,
  загрузка фото, включение/выключение видимости на сайте.
- **Заказы** — список всех заказов, состав, контакты покупателя, смена статуса
  (новый / в обработке / выполнен / отменён).
- **Пользователи** — список всех зарегистрированных, их контакты (почта, телефон/Telegram),
  блокировка/разблокировка (заблокированный не может входить, оформлять заказы и оставлять
  отзывы).
- **Настройки сайта** — текст описания бренда на главной и контакты в футере/на главной.

## 7. Запуск локально в VS Code

1. Откройте папку проекта в VS Code: `File → Open Folder…`.
2. Откройте встроенный терминал (`` Ctrl+` ``) и выполните:

   ```bash
   npm install
   npm run dev
   ```

3. Откройте в браузере http://localhost:3000

Изменения в коде подхватываются на лету (hot reload). Чтобы остановить сервер — `Ctrl+C` в
терминале.

### Полезные команды

```bash
npm run dev     # локальный запуск с автообновлением
npm run build   # прод-сборка (проверка, что всё компилируется без ошибок)
npm run start   # запуск прод-сборки локально
npm run lint    # проверка кода линтером
npm run bot     # запуск Telegram-бота-магазина (раздел 5)
```

## 9. Рекомендация по серверу (Play2Go)

Для этого сайта вся тяжёлая часть (база данных, авторизация, хранение фото) вынесена на
Supabase — самому серверу нужно только рендерить страницы Next.js, это лёгкая нагрузка.

**Рекомендуемый тариф: DE-1** (1 vCPU, 2 GB RAM, 80 GB NVMe SSD, до 1 Gbit/s, защита от
DDoS L3-L4, ≈340₽/мес).

Почему не дешевле (DE-PROMO):
- Диска 25 GB впритык: `node_modules` + сборка (`.next`) + системные пакеты легко займут
  большую часть места, а при пересборках/логах может не хватить места — сайт начнёт «лагать»
  или падать именно из-за этого, а не из-за нехватки CPU.
- Канал 100 Mbit/s вместо 1 Gbit/s — при одновременных заходах нескольких покупателей
  (особенно с холодным кэшем) урезанный канал будет ощущаться как подтормаживание сайта.

Почему не дороже (DE-2 и выше):
- Next.js SSR-страница обрабатывается за миллисекунды, а не секунды; 1 vCPU и 2 GB RAM с
  запасом хватает на десятки одновременных посетителей приватного бутик-бренда.
- Расти по нагрузке можно в любой момент, просто сменив тариф на Play2Go (DE-2 → 2 vCPU/4 GB,
  если трафик заметно вырастет) — переустанавливать ничего не нужно.

Если в будущем нагрузка ощутимо вырастет (много одновременных покупателей, тяжёлые 3D-превью
и т.д.) — следующий шаг: **DE-2** (2 vCPU, 4 GB RAM, 560₽/мес).

*Важно: развёртывание на сервере и покупка домена — отдельный шаг, в эту задачу не входил.
Здесь описана только рекомендация по тарифу для будущего деплоя.*

## 10. Что уже готово, а что — временная заглушка

- **RK — Parfum** и **RK — 3D Print** — полностью рабочие каталоги: карточки товаров, корзина,
  оформление заказа с уведомлением в Telegram, отзывы (оценка 2–5, плюсы/минусы, фото),
  шкала остатка на распив у парфюмов.
- **Telegram-бот-магазин** (раздел 5) — тот же каталог и заказы, что на сайте, прямо в Telegram.
- **Studio Pod Shade** — страница-заглушка с сообщением о разработке (по ТЗ).
- **MemoryPhone** — внешняя ссылка на memoryphone.online (по ТЗ).
- **Демо-товары и SVG-заглушки фото** (`supabase/seed_demo_products.sql`,
  `public/brand/placeholders/*.svg`) — для наглядности каталога, пока нет реальных
  фотографий. Замените/удалите их через админку в любой момент.
- **Реальная онлайн-оплата не подключена** — по вашему выбору сайт собирает заявку на
  заказ (данные покупателя приходят вам в Telegram и в админку), оплата и подтверждение —
  вручную, напрямую с клиентом.
